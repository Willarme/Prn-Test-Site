# Fixture Page Creator runs

The authenticated Page Creator can create a durable run of one to eleven selected
synthetic fixtures. The default selection is F01–F11 and the default is an unsaved
dry run. Create and Resume process one item per HTTP request. Pause stops before
the next item; reopening a run only reads its state.

## What a complete fixture run means

F01 preserves the actual blocked AC conversion report. F02–F11 compile synthetic
candidates with the existing unreviewed t01 compatibility assignment. A complete
eleven-item run therefore records one blocked control and ten builds. It does not
establish ten reviewed themes, A06 approval, live opportunity admission, visual
acceptance or publication. Model calls and model cost are both zero.

Saved runs reserve and capture one immutable version per run-scoped fixture page.
Dry runs write private run records, input evidence and artifacts, but never reserve,
capture or register PageVersions. Their authenticated previews verify the exact
run, input and output hashes and add a DRAFT banner to the response. Preview styles,
scripts, forms and outbound connections are disabled; these content views are not
fidelity or browser acceptance evidence.

## Operation and recovery

- `POST /api/admin/page-runs` accepts a UUID `Idempotency-Key`, mode, dry-run flag,
  one to eleven distinct fixture IDs, matching count and a reason. It returns202
  and `run-<UUID>` after inserting every ordered item. The UI retains that run ID
  in the URL before sending. The same key and normalized request returns the
  original run; a changed request conflicts.
- `GET /api/admin/page-runs/<run_id>` reads durable progress. Unknown or foreign
  records are unavailable. No raw input context or filesystem path is returned.
- `POST /api/admin/page-runs/<run_id>/advance` requires the current revision.
  It claims one item with a two-minute lease, performs deterministic fixture work,
  and records its outcome with the exact attempt and revision fences.
- A stale request cannot claim another item. An interrupted request can resume
  after its lease expires, retaining the original execution timestamp, input,
  page identity and version. A written artifact whose completion record was lost
  is verified and recovered. Terminal items are never regenerated by Resume.
- Twenty attempts per item bound the aggregate. Exhausted unfinished work stays
  visibly unresolved and requires operator investigation; the store does not
  fabricate a failed build or successful outcome. Broader operator recovery is
  outside this source unit.
- Fixture input/package/executor changes refuse further execution of an old run.
  Existing history remains readable. Supported historical dry artifacts can still
  be previewed from their private, hash-bound input evidence.

No detached worker is assumed. Closing the page stops dispatching further items.
An uncertain response stops the client; it never silently retries a mutation.
Every endpoint authenticates before resolving private parameters or touching the
package/store. Writes additionally require the configured same origin. Shared
owner-session authentication does not identify which individual owner clicked.

## Runtime preparation

Apply migration `00032_door_page_runs.sql` through the existing authorized migration
process before using the shared SQL backend. It provides service-only transactional
create/claim/complete functions, revision checks, audit history and deny-all client
RLS. A configured database failure never falls back to a local file.

Set `PRN_DOOR_V44_ARTIFACT_ROOT` to a private absolute directory backed by storage
that survives and is shared across the intended requests. Serverless temporary
storage alone does not meet that requirement. `PRN_RUNTIME_STORE=file` with an
isolated `PRN_DEV_DB_PATH` is the existing local fixture backend. All application
runtime data and artifacts remain outside the source package.

The fixture generator is `tools/door-v44/package-run-fixtures.ts`. The checked-in
package contains complete synthetic inputs, a bounded F01 report, and a manifest
of the actual executor dependency closure. Runtime validates those hashes before
writes. `tools/door-fixture-runtime-tracing.mjs` includes that explicit public
source/input closure in the relevant Next bundles. Hash identity is not an
attestation that an executor ran on a second host.

Live mode currently returns a whole-batch422 listing the missing live admission,
approved theme rotation, shared budget authority and writer/critic orchestration.
It makes no calls and writes no run. These are explicit remaining integrations,
not simulated live preflight results. No deployment, migration application,
browser check, production activation or public indexing is implied by this unit.
