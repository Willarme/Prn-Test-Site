# Private fixture execution package

This package contains ten synthetic compiler inputs and the actual blocked F01 conversion result. It supplies no production review, theme approval, independent QA, execution attestation, or publication authority. Tiny generated images, fixture source/protocol/hazard records and the synthetic t01 assignment remain test material.

The offline generator `tools/door-v44/package-run-fixtures.ts` reads the existing corpus factory and frozen AC conversion. Server execution reads only this complete, pinned package and the shipped source closure listed in its manifest. No runtime import of tests or developer CLI occurs. Package JSON bytes are excluded from Git newline conversion; execution sources permit only their separately pinned raw, LF and uniform CRLF representations.

Regeneration is an explicit source change. The generated pin module is outside the source closure to avoid a self-referential hash. Every other local transitive import of the executor and input loader, plus package/lock files, is pinned. Deployment must ship those listed source files; absence or drift fails preflight before storage writes. These checks establish byte identities, not proof that a hosted process executed those sources.

Run identity mapping is deterministic and isolated per tenant/run/fixture. Saved execution reserves and captures before compiling. Dry execution writes only the private run-scoped artifact/input namespace; it never reserves, captures, registers or publishes a catalogue page. Dry preview verifies historical saved input and receipt hashes without requiring the current fixture package.

F01 remains `BLOCKED_CONTROL_DERIVATIVE`. A completed eleven-item run means ten synthetic built candidates and one blocked control, never a full corpus or H01–H18 pass. Interrupted storage operations must resume with their original command, audit fields and package pins.
